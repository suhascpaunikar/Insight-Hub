# Reverting to the HTML prototype

The console was ported onto [@cloudflare/kumo](https://www.npmjs.com/package/@cloudflare/kumo)'s
real components. Those are React, so the port brought a bundler with it and took away
the thing the prototype used to be best at: clone it, open `index.html`, done.

The build before that is not lost and not in a branch that might get tidied away. It
has its own tag.

| Ref | What it is | On the remote? |
|---|---|---|
| **`html-prototype`** | A branch on `b28bd21`, the last commit before the port. | **Yes** — this is the one to rely on. |
| **`html-prototype-v1`** | An annotated tag on the same commit, whose message says what the build was and why it is kept. | **No.** See below. |

Both point at the same tree: four static HTML documents, vanilla ES modules, the
design system mirrored by hand in `assets/css/`. No bundler, no runtime dependencies.

> **The tag is local-only.** The session that made it could push branches but not
> tags — `refs/tags/*` came back `403` for annotated, lightweight and explicit-refspec
> pushes alike. The branch carries the same commit and is pushed, so nothing is at
> risk; the tag is just nicer to have, because a branch can be deleted by anyone
> tidying up and a tag reads as "kept on purpose".
>
> If you want it on the remote, you have the permissions this session did not:
>
> ```bash
> git fetch origin html-prototype
> git tag -a html-prototype-v1 origin/html-prototype -m "The last no-build-step HTML prototype, before the Kumo port"
> git push origin html-prototype-v1
> ```

---

## Just look at it, or run it

Nothing is installed and nothing in your current checkout changes:

```bash
git fetch origin html-prototype
git switch html-prototype
python3 -m http.server 8000      # then open http://localhost:8000
```

`git switch -` puts you back.

> A static server rather than `file://`: the pages are ES modules, which browsers
> refuse to load on the `file:` scheme.

## Actually revert the project to it

```bash
scripts/revert-to-html.sh --check    # what would change, and nothing else
scripts/revert-to-html.sh            # do it (asks first)
```

The script finds the build for itself, trying `html-prototype-v1`, then
`origin/html-prototype`, then a local `html-prototype` branch — so it works whether or
not the tag ever reaches the remote. `--ref=<anything>` overrides that. It restores the
working tree, stages it, and stops. The commit is yours to make:

```bash
git commit -m "Revert to the no-build-step HTML prototype"
```

Changed your mind before committing — `git reset --hard HEAD`.

### What it does, and why that way

It runs `git read-tree -u --reset <ref>`, which makes the index and the working tree
match that commit **and deletes what the commit does not have**. The
obvious alternative, `git checkout html-prototype-v1 -- .`, restores `assets/` and
leaves `src/` sitting beside it — a half-reverted tree that runs neither build, with
two `index.html` entry points disagreeing about which one is real.

It deliberately does **not**:

- **touch history.** The port's commits stay where they are. The revert lands as an
  ordinary commit on top, so both builds stay reachable and `git checkout -` on a
  clean tree brings the Kumo one straight back.
- **run with uncommitted changes.** It refuses and prints `git status` instead. A
  revert that silently ate working-tree changes would be the worst failure available
  to it.
- **touch `node_modules/`.** Ignored by git, harmless to leave, and expensive to
  reinstall if you change your mind.

It does remove `dist/`, because that is gitignored and `read-tree` will not touch it —
and a stale `dist/` served by a static server looks exactly like the prototype while
being the Kumo build.

## What reverting costs

The two builds are not feature-equivalent, and the gap is all in the same direction.
The HTML prototype is the mirror; every component in it was built by hand to match
Kumo. Going back means:

- **The components are copies again.** A Kumo release no longer moves this console.
  `assets/css/kumo-tokens.css` was generated by `scripts/kumo-tokens.mjs` from the
  installed package, so it is only as current as the last time someone ran it.
- **Four corrections go with it.** The port found things the mirror had wrong — a
  `Tooltip.Provider` that does not exist, `Text` display sizes that are deprecated,
  eleven components missing from the CLI's inventory, and a `Table` striping variant
  that cannot be passed because it is not there. §11 of the guideline records all of
  them; the tagged tree predates every one.
- **Quick search goes back to being a placeholder.** It is a dead field over the words
  "Placeholder in this prototype". The port made it a real `CommandPalette` over the
  campaigns, segments and templates already in the store.
- **`pages.yml` goes back to uploading the repo** rather than building it, which is
  correct for that tree and wrong for this one. The script restores the right version
  along with everything else.

What you get back is the one thing the port genuinely lost: a console that needs no
install, no Node, and no network to run.

## If the refs are missing

The script tries three and tells you which it used. To get them back:

```bash
git fetch origin html-prototype:html-prototype   # the branch — the reliable one
git fetch --tags origin                          # the tag, if the remote has it
```

Shallow clones fetch neither by default, which is the usual cause.

If every ref is gone, the commit is **`b28bd21`** — the parent of the first port
commit, `6eef25a`. It is reachable from this branch's history for as long as that
history exists, and the script will take it directly:

```bash
scripts/revert-to-html.sh --ref=b28bd21
```
